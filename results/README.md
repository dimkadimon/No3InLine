# Interpreting Table 1

`lower-bounds.csv` is the publication table, calculated by `../scripts/comparison.py`. `W` is the largest separately certified project configuration presented for that board, not the outcome of an exhaustive search over every embedding. `B_ref` is a lower bound on the **unrestricted** problem, compared at exactly the stated side. It is the maximum of the following specified transfers, **not a proof of the worldwide best**. A centred symmetry of a source can be lost in a crop or embedding; the Q/H/U column describes only the project witness. All grids have zero-based integer coordinates and use Euclidean collinearity.

- **C:** `3(q−1)` on side `2q` (prime `q`, HJSW). **R:** `6(q−1)` on side `4q` (`q ≡ 1 mod 12` prime, paper 38). Given a source of size `b` and side `a`, count `b − 4 max(a−n,0)`. Before the target scale these particular bounds increase with `q`; afterwards they decrease. It suffices to test the neighbouring admissible primes in each family.
- **K:** the 146 version-pinned original side-92–300 sets in the paper 22 v4 bank. For each larger source, `p22-crops.csv` records the maximum actual point count in **all** axis-aligned integer windows of target side `n`, with a maximizing lower-left corner. Other sets embed unchanged. The often cited 504 is an actual crop at side 293, not an external optimum. The source set has side 300 and 524 points; both `[3,295]²` and `[4,296]²` contain 504 points.
- **S:** the 282, 421 and 810 published insertions (paper 47 §8, v1) on top of the three `3(q−1)` frames. The direct same-board totals are 24,306, 48,421 and 96,816. Use the same crop/embed inequality at other sides. A verified literal extension is not to be confused with a larger net-gain solution obtained after deletions.
- **F:** integer counts actually stated in the dated public reports linked in `forum-counts.csv`. The transfer is by the same inequality; these reports were not independently re-run as external coordinate sets in this release. This separates evidence of a *reported* stronger lower bound from a weak, fully downloadable comparator. On side 293 the best reference here is 512, not 504; on 389 it is 652, not 576; on 773 it is 1,244, not the bare-ring count 1,152; on 4,037 it is 6,118, not 6,048. Favour a coordinate-backed source if the same count is also reported in a post.

The `excess_vs_1.5n` column is `W−3n/2` at the actual board side; it is **not** `W−B_ref`. Neither difference, positive or negative, proves a global record or an upper bound. The comparison is as of **19 November 2026**, not a live ranking.

`python3 scripts/comparison.py` from the root calculates the whole table from the stored counts and certificates, then compares it to both the CSV and the exact LaTeX rows. `--write` rewrites the three derived files. After `python3 scripts/restore_inputs.py --group station --fetch`, `--audit-sources` additionally checks every P22 point set for collinear triples and enumerates all its relevant windows from the raw points; it also checks the versioned P47 headers. The earlier exchange verifier independently reconstructs the public supersets. See `verification/` for the actual replays.
